## 1. 개요: 에이전트 워크플로를 위한 단일 패스 의사결정 모델

클라우드플레어(Cloudflare)가 텍스트, 구조화 데이터(JSON), 이미지, 오디오(WAV/MP3), 비디오(MP4/WebM)를 통합 처리하는 신규 오픈 가중치 의사결정 모델 **Clef-omni**를 허깅페이스(Hugging Face)에 전격 공개했습니다. 

기존 LLM 기반 에이전트 파이프라인은 텍스트 생성 후 복잡한 정규식이나 JSON 스키마 유효성 검사기를 거쳐 출력을 파싱해야 했으며, 멀티모달 데이터를 처리할 때 음성 인식(STT)과 비디오 프레임 추출을 개별 모듈로 직렬 연결해야 하는 구조적 한계와 높은 지연 시간이 존재했습니다. Clef-omni는 이러한 다단계 파이프라인을 대체해, 모든 입력 모달리티와 질문 스키마를 단 한 번의 순전파(Single Forward Pass)로 처리하여 각 허용 항목에 대한 정형화된 확률(Logits/Probabilities)을 직접 출력합니다.

---

## 2. 모델 아키텍처 및 상세 스펙

* **전체 파라미터**: 30B (300억 개)
* **활성화 파라미터 (Active Parameters)**: 약 3B (토큰당 라우팅되는 Mixture-of-Experts 구조)
* **컨텍스트 윈도우**: 64,000 토큰 (64K Native Context)
* **기반 아키텍처**:
  * **멀티모달 백본**: 네이티브 비전 및 오디오/비디오 인코더가 결합된 MoE 트랜스포머 백본.
  * **Joint Schema Head**: 백본의 최종 은닉 상태(Hidden States)를 참조하여 질의 스키마의 각 질문(이진 참/거짓, 다중 선택, 스칼라 점수)으로 증거를 라우팅하고, 후보 옵션들의 확률 분포를 산출하는 전용 트랜스포머 헤드.
* **지원 입력 모달리티**: 텍스트, 네이티브 JSON, 단일/다중 이미지, 오디오(WAV, MP3), 비디오(MP4, WebM)
* **출력 구조**: 자유 텍스트 토큰 디코딩 루프가 배제된 정형화된 옵션별 로짓 (Softmax 확률 출력)
* **라이선스**: Apache 2.0 (상업적 이용 및 자체 수정 허용)

## 3. 벤치마크 점수 및 성능 지표

Clef 패밀리는 Decision Index 및 실무 에이전트 라우팅 벤치마크에서 기존 단일 패스 결정 모델 대비 우수한 분류 정확도와 빠른 반응 속도를 기록했습니다.

* **표준 언어 및 함수 호출 벤치마크**:
  * **MMLU**: 90.3%
  * **GSM8K**: 80.8%
  * **WinoGrande**: 93.5%
  * **BFCL (Berkeley Function-Calling Leaderboard)**: 케이스 정확도 98.5%
* **실무 워크플로 의사결정 정확도**:
  * **인보이스/영수증 자동 처리 (Primary-Action)**: 86.2%
  * **고객 서비스 티켓 라우팅 (Exact-Actions)**: 76.3%
  * **보안 인시던트 분류 및 긴급도 판별**: 62.9%
* **지연 시간 (Latency)**:
  * 순수 단일 패스 연산 방식을 채택하여 생성형 토큰 디코딩 단계가 생략됨에 따라, 단일 GPU 추론 환경에서 중간값(p50) 기준 약 200 ms 내외(경량화 버전인 Clef-flash의 경우 약 39 ms)의 반응 속도를 달성했습니다.

## 4. 로컬 구동 및 프레임워크 지원 여부

* **추론 엔진 연동**:
  * **SGLang**: 공식 런치 레시피 및 커스텀 헤드 지원 쿡북 제공.
  * **vLLM**: 공식 배포 가이드와 함께 서빙 컨테이너 및 OpenAI 호환 API 연동 엔드포인트 지원.
  * **Hugging Face Transformers**: 커스텀 모델 코드(`joint_schema_model.py`)와 `AutoProcessor`를 통한 단일 스크립트 구동 가능.
* **로컬 환경(Ollama / llama.cpp)**:
  * 일반적인 자기회귀형 텍스트 생성 모델과 달리 출력단에 `joint_head`가 결합된 형태이므로, 표준 Ollama의 대화형 모델 형식 대신 로컬 vLLM/SGLang 인스턴스를 통한 서빙이 권장됩니다.
  * 단일 H100 또는 A100(80GB) 환경에서는 양자화 없이 FP16/BF16으로 단독 서빙이 가능하며, 양자화 적용 시 24GB VRAM을 갖춘 개인용 워크스테이션 환경에서도 로컬 라우팅 파이프라인을 구축할 수 있습니다.
