검색 특화 AI 스타트업 지나 AI(Jina AI)가 저사양 하드웨어 환경에서도 고속·고정밀 문서 파싱을 수행할 수 있는 멀티모달 비전 모델 **jina-ocr-v1**을 오픈소스로 공개하고 가중치(Weights)를 배포했습니다.

기존 비전 언어 모델(VLM)을 활용한 문서 파싱은 다중 모달리티 연산과 긴 출력 토큰 생성으로 인해 높은 서빙 비용과 지연 시간을 유발했습니다. jina-ocr-v1은 고효율 압축 비전 인코더와 희소 전문가 혼합(Sparse Mixture-of-Experts, MoE) 디코더, 그리고 추측 디코딩(Speculative Decoding) 기술인 FastMTP를 결합하여 엔트리급 GPU에서도 실시간에 가까운 초당 2.57페이지의 파싱 처리량을 달성했습니다.

---

### 1. 모델 아키텍처 및 상세 스펙

jina-ocr-v1은 DeepSeek-OCR의 효율적 설계를 계승·발전시킨 구조로 제작되었습니다.

| 항목 | 상세 규격 |
| :--- | :--- |
| **총 파라미터 수** | 총 3.4B (34억 개) |
| **활성 파라미터 (Active Params)** | 토큰당 약 570M (5억 7,000만 개) |
| **최대 컨텍스트 길이** | 32,768 토큰 (32K Window) |
| **비전 인코더 타워** | DeepEncoder (SAM + 16배 압축 합성곱 + CLIP-L 결합, 약 380M) |
| **이미지 해상도 및 토큰** | 1024×1024 글로벌 뷰(256 토큰) + 최대 9개 동적 로컬 타일(최대 1,156 토큰) |
| **디코더 구조** | DeepSeek-3B-MoE (12개 레이어, 64개 라우팅 전문가 중 Top-6 활성화 + 2개 공유 전문가) |
| **추론 가속 엔진** | FastMTP 재귀 단일 초안 블록 (K=3 단계 투기적 생성, 무손실 검증) |
| **라이선스** | 가중치: CC BY-NC 4.0 / 추론 코드: Apache 2.0 |

- **FastMTP 추측 디코딩**: OCR 출력의 높은 국소 규칙성을 활용하여 K=3단계 미래 토큰을 단일 초안 블록으로 재귀 예측합니다. 디코더의 그리디(Greedy) 검증을 거치므로 표준 자기회귀 생성과 완전히 동일한 무손실(Lossless) 텍스트를 생성하면서도 스텝당 평균 2.73개 토큰을 일괄 확정합니다.
- **검증 가능한 보상 기반 사후 학습**: 강화학습(GRPO) 단계에서 수식, 표, 문서 구조를 결정론적 코드로 검증하고 부분 점수를 차등 부여하는 고밀도 보상(Dense Verifiable Rewards) 방식을 적용하여 환각 현상을 억제했습니다.

### 2. 주요 벤치마크 및 처리량 성능

jina-ocr-v1은 문서 파싱 정확도와 저가형 하드웨어 서빙 처리량 모두에서 상위권 지표를 기록했습니다.

| 벤치마크 / 평가 지표 | jina-ocr-v1 점수 | 비교 모델 대비 성과 |

| **OmniDocBench v1.6** | **91.14점** (종합) | 복합 표·수식 레이아웃 파싱 전반에서 고득점 달성 |

### 3. 로컬 구동 및 배포 환경 지원

jina-ocr-v1은 온프레미스 인프라 및 단일 GPU 기반 로컬 개발 환경에서 즉시 구동될 수 있도록 다양한 서빙 런타임을 공식 지원합니다.

- **Hugging Face Transformers**:
  단일 파이썬 스크립트(`AutoModelForCausalLM`, `AutoProcessor`)에서 `trust_remote_code=True` 옵션으로 BF16 가중치 로드가 가능합니다.
- **vLLM (FastMTP 가속 완벽 지원)**:
  `vLLM ≥ 0.21` 환경에서 전용 레지스트리 함수(`register()`)를 등록하여 FastMTP(K=3) 스페큘러티브 디코딩을 활성화할 수 있습니다.
- **SGLang 및 컨테이너 배포**:
  SGLang 서버 런치 스크립트를 통한 호스팅과 함께, 허깅페이스 공식 도커 명령어(`docker model run hf.co/jinaai/jina-ocr-v1`)를 이용해 즉각적인 엔드포인트 컨테이너화가 지원됩니다.
- **Ollama / llama.cpp 로컬 구동**:
  커뮤니티를 통해 GGUF 양자화 변환 규격이 배포되고 있으며, 570M 활성 파라미터 특성상 VRAM 요구량이 낮아 8GB~16GB VRAM을 갖춘 개인용 데스크톱(Apple Silicon Mac, RTX 4060/4070 등)에서도 손쉽게 구동할 수 있습니다.
